## New Capabilities

### Adapter Capability Query
```bash
# Query all adapters
harness adapter capability

# Query specific adapter
harness adapter capability --adapter mock-python
```

**Output format**:
```json
{
  "adapter_id": "mock-python",
  "provider": "mock",
  "capabilities": ["echo", "demo"],
  "max_prompt_length": 1000000,
  "supports_raw_prompt": true,
  "supports_templates": true,
  "supports_argv": true,
  "verification_mode": "argv",
  "trust_level": "verified_local",
  "availability": "present"
}
```

### Adapter Registration with Capabilities
```bash
harness adapter register \
  --id my-adapter \
  --provider my-provider \
  --command-template "..." \
  --capabilities "code-generation,code-analysis" \
  --max-prompt-length 4000 \
  --verification-mode argv
```

## Known Limitations (For v0.8+)

1. **Verification commands still use shell mode** by default
   - Planned: `--verification-mode argv` enforcement
   
2. **Capability validation not enforced**
   - Planned: Block/warn if task requires unavailable capabilities
   
3. **Real provider smoke tests deferred**
   - Codex and Claude adapters not tested with actual providers
   - Planned: v0.8 smoke gates once capabilities are validated

4. **Max prompt length not enforced**
   - Adapters declare limit but truncation not yet implemented
   - Planned: v0.8 validation with warnings

## v0.8 Roadmap

Based on v0.7 foundation, v0.8 should implement:

1. **Capability Validation**: Reject/warn if task requires capabilities adapter lacks
2. **Shell-Free Verification**: Enforce `--verification-mode argv` option
3. **Prompt Truncation**: Enforce max_prompt_length with warnings
4. **Real Provider Smoke**: Test Claude and Codex adapters if available
5. **Skill/Tool Routing**: Use capabilities to select adapters for tasks
