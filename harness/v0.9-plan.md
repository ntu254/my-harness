# v0.9 Plan: Core Gate Hardening

## Why

The development plan says v1.0 requires stable evidence freshness, completion
gates, human gates, and benchmark proof. v0.8 restored routing, skills,
capabilities, human gate records, and route benchmarks. v0.9 hardens the end of
the lifecycle so a task cannot be closed on stale or incomplete proof.

## Scope

- Add final completion reports.
- Add `complete` command with blocking gates.
- Detect stale evidence from git head and dirty file state.
- Separate required and optional capability gaps.
- Block completion on missing required capabilities.
- Mark optional gaps and skipped checks as weak proof.
- Add approval scope and expiry.
- Allow high-risk runs through a valid scoped approval.
- Add benchmark scoring for quality, cost, adaptiveness, and durability.

## Out Of Scope

- Provider-specific transforms.
- Multi-agent scheduling.
- Live UI/browser automation.
- Learned benchmark scoring.

## Acceptance

- `harness report final --json` returns pass, weak, or blocked with evidence and risk details.
- `harness complete` updates a story only when gates pass.
- Stale evidence blocks a final report.
- Missing required capability blocks proof policy and completion.
- Approval scope mismatch is invalid.
- Expired approval is invalid.
- High-risk run can execute with a valid scoped approval.
- `harness bench run --json` reports quality/cost/adaptiveness/durability scores.
- Fresh DB validation applies schemas 1 through 7.
